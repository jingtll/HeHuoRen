# 首页学院院徽的存储建议

分析更新日期：2026-10-03；院徽原素材体积测量日期：2026-10-02。

**建议：** 将确认后的院徽整理为小尺寸、单枚文件，保存在 `apps/web/src/assets/colleges/`，由 Vue/Vite 代码显式导入；官网图片地址只留作内部来源记录，不让首页运行时依赖学校站点。先把横幅或截图中的院徽真正裁成独立图片并压缩，不能只用 CSS 裁视窗，因为浏览器仍会下载完整原图。对院徽这种边线和小字较多的图，应先检查压缩后的可读性，再选 PNG、WebP 或官方矢量格式。

## 与项目计划的匹配

计划书把低配单机列为优先方向，服务器规格和预算仍未确定；暂以单台 Linux、2 核 / 2GB 为主要部署基线（[计划书，第 1.3–1.4 节](../../禾伙人-项目开发计划书.md)，[第 1.3 节](../../禾伙人-项目开发计划书.md#13-已确认的决策)第 88 行，[第 1.4 节](../../禾伙人-项目开发计划书.md#14-本计划采用的技术默认值)第 96 行）。部署技术表列出 Nginx、systemd 和 PostgreSQL，第 5.5 节写明由 Nginx 提供构建后的静态文件、systemd 运行单个 NestJS 进程（[第 5.1 节，第 282 行](../../禾伙人-项目开发计划书.md#51-技术栈)、[第 5.5 节，第 351 行](../../禾伙人-项目开发计划书.md#55-构建与部署拓扑)）。生产部署还未配置；计划书说明公开演示站不是开发前提，若不购买服务器，可以本地演示（[第 0.1 节，第 27 行](../../禾伙人-项目开发计划书.md#01-当前进度2026-10-02)、[阶段八，第 690–704 行](../../禾伙人-项目开发计划书.md#阶段八部署演示与简历材料)）。

计划书没有列出对象存储或 CDN 服务及其预算。把 27 张小图作为 Web 构建产物随现有单机静态站提供，不增加独立对象存储/CDN服务的固定费用；但这**不代表流量没有成本**，服务器带宽或出站流量仍按最终主机套餐计费。项目计划书当前未确定提供商、流量额度或具体价格，不能从计划推算实际账单。

## 当前前端依据

当前首页组件只有标题文案和嵌套路由出口，还没有院徽内容（[HomeView.vue，第 1–5 行](../../../../apps/web/src/views/HomeView.vue)）。Web 使用 Vite 构建（[apps/web/package.json，第 6–9 行](../../../../apps/web/package.json)），Vite 配置启用 Vue 与 Tailwind 插件，另有本地 API 代理，没有另配 CDN 或资源主机（[vite.config.ts，第 6–9 行](../../../../apps/web/vite.config.ts)）。仓库已经把品牌图放在 `apps/web/src/assets/hehuoren-logo.png`；它目前约 1.09 MB，可作为“资源可随 Web 前端管理”的现有例子，但也说明图片需要先压缩。

Vite 官方文档说明，导入的静态资源会进入构建资源图并获得带哈希的文件名；小于内联阈值的资源会转成 Base64。院徽应显式用 `?no-inline`，或设置合适的 `assetsInlineLimit`，避免把图片塞进 JS/CSS；这样图片可作为独立文件缓存。Vite 对普通应用也建议优先导入资源，而不是放进 `public` 目录。[Vite：静态资源处理](https://vite.dev/guide/assets.html#static-asset-handling)

计划部署方式与该做法相容：Vite 生成的静态文件由 Nginx 从本机目录提供。Nginx 官方指南说明，可以用 `root` 将图片 URL 映射到本地目录文件，且可以让同一 Nginx 实例把其他请求代理给应用进程。[Nginx：Serving Static Content](https://nginx.org/en/docs/beginners_guide.html#static_content)

## 原素材体积实测

已确认的25张院徽原始素材合计4,456,002字节，约4.46 MB（十进制）。其中23张官网图片响应体合计4,177,177字节；用户提供的经济学院PNG为235,797字节，信息工程学院PNG为43,028字节。官网图片均返回HTTP 200；不包含HTTP头等传输开销。素材地址与用户文件来源见 [colleges.json](colleges.json)。

较大的原图包括人文学院1,268,313字节、动物科技学院938,706字节、水产学院759,542字节。当前研究预览使用CSS视窗显示院徽区域，不会减少实际下载的原图体积；产品应使用真正裁取、压缩后的独立图片。此处测量的是原始素材，不能当作最终首页图片包大小。

## 三种方式的成本与适用性

| 方式                     | 成本和维护                                                                               | 当前建议                             |
| ------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------ |
| 项目自有静态文件         | 随前端部署，使用既有Nginx；占用少量磁盘及现有套餐带宽，不增加独立图片服务                | 推荐                                 |
| 直接使用学院官网图片链接 | 图片请求直接发往学院网站；地址变化、访问限制及加载速度由外部站点控制，本站无法保证稳定性 | 官网链接仅保留作来源依据             |
| 单独对象存储/CDN         | 需核对存储、请求、出站流量及套餐费用，还需维护额外配置；具体金额取决于服务商             | 当前规模暂不引入，实际需求增长后评估 |

## 粗略流量示例

以下只是容量估算，不是素材测量或账单报价。假设每枚院徽经过实际裁切、压缩后为约 20 KB：

- 27 枚合计约 `27 × 20 KB = 540 KB ≈ 0.54 MB`。
- 假设首页每次都完整加载 27 枚，且 10,000 次浏览都没有命中浏览器缓存，则图片正文传输约 `0.54 MB × 10,000 = 5.4 GB`。
- 这个估算不含 HTTP 请求/响应头、TLS、重传等开销；用户返回页面时，浏览器缓存通常会减少重复传输。实际账单取决于主机套餐、缓存策略和真实访问量。

因此先用压缩后的本地静态资源，随现有 Nginx 单机部署；暂时不单独采购对象存储或 CDN。等部署提供商、流量套餐和实际访问量确定后，再用账单或监控验证带宽成本。如果未来素材变成用户上传、需要独立更新，或流量和可用性要求显著增长，再评估对象存储/CDN。

## 院徽文件整理要求

1. 每个文件只含单枚院徽，使用实际裁切后的图像文件，页面按需保留学院名称作为文本标签。
2. 优先从院系官网或用户提供的原始素材确认标识，再生成规范尺寸的产品资源；官网 URL 放在来源记录里，不当作运行时图片地址。
3. 使用 Vite 导入并禁用内联，构建后由 Nginx 同源提供；可为静态图片设置合理的浏览器缓存。
4. 本文件中的 `20 KB/枚` 和流量数字是给预算讨论用的假设，之后应以最终资源目录的实测文件大小替换。
